The Backdoor in the XZ Utils Compression Library, 2024

Event date: October 2021 to 29 March 2024 · Read from instrument version 0.3 · Industry and Economy collection

What happened

In 2024 a backdoor was found in XZ Utils, a compression library linked by remote-login servers on many Linux systems. A contributor had gained release authority from the project's single unpaid maintainer, hid the code in unused binary test files, and put its activation only in the release package. It reached development and rolling releases but not stable ones, and was found by chance from a slowdown in logins.

Tier

Adversarial, not military action. A deliberate supply-chain compromise, not placed at the military-action tier: the actor is unidentified and no government has attributed it.

Findings

  • F-1, Reviewed means readable, and the release is generated from the repository. The payload sat in binary files, and its activation only in the release package.
  • F-2, The pace of intake is part of the defense. Accounts pressed distributions to take the new versions quickly.
  • F-3, A change in who can release is a change to the product. The contributor gained release authority over about a year.

For asset owners

Annex A of the instrument, in full. It is written for owners and operators, and it states no requirement.

A.1 What This Annex Is

This annex is for maintainers of open-source components, the operating-system distributions that package them, and the organizations that build products and systems on them. It is not a finding and states no requirement. The recommendations of Section 8 are addressed to the framework; this annex is addressed to an operator. It has three parts, each drawn from a section of the instrument: a self-check that turns the event’s elements (Table 4-1) into questions an operator answers about the operator’s own system (A.2); the actions published, each stated as its publisher’s, with this instrument’s own marked and tied to a finding (A.3); and a plain-language account an operator can give a board (A.4).

A.2 Would It Happen Here?

The instrument reads the event against the design basis. The self-check reads the same event against one operation. Each question is keyed to the element of Table 4-1 it comes from. A “no” or an “I don’t know” is not a failure of the operator; it is that operation’s finding, and the place to start.

A.3 What to Do Now

A.3.1 Review What Is Readable, and Generate the Release

No authority has published an action for maintainers that this instrument reads beyond the advisory below. This step is this instrument’s, from F-1: require that reviewed source be readable, and that the release be generated from the repository, not carry files of its own.

A.3.2 Govern the Pace of Intake and the Right to Release

On 29 March 2024 the Cybersecurity and Infrastructure Security Agency advised users to downgrade to an uncompromised version, and Debian rolled back the same day. These steps add the instrument’s own, from F-2 and F-3: take upstream versions at a pace that leaves time for review; and treat a change in who can release a component as a change to the product.

A.4 For the Board

In 2024 a backdoor was found in XZ Utils, a compression library that Linux distributions package and that many programs, including remote-login servers, link against. The project had one unpaid maintainer, who over about two years was pressed by accounts, probably fake, to hand it on, and a contributor gained the authority to release it. The contributor hid the backdoor’s code in binary test files that no test used and put the step that activated it only in the release package, not in the repository. Other accounts then pressed distributions to take the new versions. It reached development, beta, and rolling releases but not stable ones. An engineer at Microsoft noticed that failed logins were taking about half a second longer, traced it, and reported it on 29 March 2024; the government advised downgrading that day, and distributions rolled back. No use of it is recorded, and no government has attributed it. The lessons are that reviewed code must be readable, that a release must be built from what was reviewed, and that a change in who can release a component is a change to the product. Any organization that builds on open source has the same exposure. The questions in this annex show management whether this organization does, and most of the answers cost little to find.
